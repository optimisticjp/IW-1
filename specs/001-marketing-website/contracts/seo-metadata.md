# Contract: SEO Metadata & Structured Data

**Feature**: 001-marketing-website | **Type**: per-page metadata + JSON-LD interface

Every route resolves an `SeoMeta` object consumed by `BaseLayout` via `lib/seo.ts`; structured data is emitted by `lib/schema.ts`. Temporary values are allowed until final content (FR-042/FR-044); the **seams are mandatory now**.

## SeoMeta shape

| Field | Required | Notes |
|---|---|---|
| `title`* | yes | Unique per page; ≤ ~60 chars target |
| `description`* | yes | Unique per page; ≤ ~160 chars |
| `canonical`* | yes | Absolute URL from site base + path |
| `robots` | no | Defaults to index,follow; overridable (e.g. `noindex` for utility pages) |
| `ogTitle` / `ogDescription` | no | Fallback to title/description |
| `ogImage`* | yes | Placeholder OG image allowed; has dimensions |
| `ogType` | no | `website` \| `article` |
| `twitterCard` | no | Defaults `summary_large_image` |

## Per-page requirements (FR-041/FR-042/SC-014)

- Exactly **one `<h1>`** per page; logical heading order; semantic landmarks (`header`, `nav`, `main`, `footer`).
- Unique `title` + `description` on every route.
- Correct `canonical` on every route; meaningful URL matching the route map in `plan.md`.
- OG/Twitter tags present on every route.

## Structured data (`lib/schema.ts`) integration points

| Builder | Applied to | Notes |
|---|---|---|
| `Organization` | site-wide (home/base) | Name, logo, sameAs (placeholder social links) |
| `Service` | each service page | Name, description, provider |
| `Article` | each insight | Headline, author, dates (placeholder allowed) |
| `BreadcrumbList` | nested pages | Reflects route hierarchy |
| `FAQPage` | pages using `FaqModule` | From FAQ entries |

Placeholder values permitted; builders must emit valid JSON-LD shape now so real values slot in later.

## Site-wide mechanics

- **Sitemap**: generated by `@astrojs/sitemap` at build from the route set.
- **robots.txt**: `public/robots.txt`, placeholder-friendly (launch-configurable; may `Disallow: /` in non-production via env-driven build if desired — deferred).
- **Internal linking**: case studies ↔ services (FR-017), pillar ↔ services, contextual CTAs — encoded in content refs.
- **Images**: every image carries required `alt` (or `decorative:true`) and dimensions (CLS-safe).

## Placeholders (replace later)

`site` base URL, final titles/descriptions, real OG images, real social `sameAs` links, and real organization details are placeholders until content is supplied. None block the build.

## Test hooks

`tests/unit/seo.test.ts` asserts: every builder emits schema-valid JSON-LD for sample input; `lib/seo.ts` produces a complete `SeoMeta` (title/description/canonical/ogImage) for representative pages.
